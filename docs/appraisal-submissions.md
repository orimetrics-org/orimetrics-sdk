# Appraisal submissions

`client.appraisals` submits a visitor's vehicle and contact information to a selected dealership.
It creates no valuation, offer, inventory, payment or email. The receipt reference grants no access
to private appraisal details. The website owns dealership selection, consent controls and Turnstile.

## Form and submission

```ts
import type { AppraisalSubmission } from "@orimetrics/sdk";
import { validateAppraisalSubmission } from "@orimetrics/sdk";

const form = await client.appraisals.getForm(dealershipSlug);
if (!form.enabled || !form.privacyNotice.url || !form.privacyNotice.version) {
  // Hide submission controls.
  return;
}

// Render the notice and obtain explicit consent. Configure Turnstile using form.turnstile.
// Generate once per logical submission, outside the submit/retry callback.
const idempotencyKey = crypto.randomUUID();
const submission: AppraisalSubmission = {
  customer: {
    displayName: "Visitor name",
    contacts: [{ kind: "phone", value: "099 123 4567", countryCode: "EC" }],
    preferredContactChannel: "whatsapp",
  },
  vehicle: {
    submittedBrand: "Toyota",
    submittedModel: "Corolla",
    modelYear: 2020,
    submittedCity: "Quito",
    conditionDescription: "Good condition; requires inspection.",
    odometerValue: 50000,
    odometerUnit: "km",
    expectedPriceUsd: "15000.00",
  },
  privacyVersion: form.privacyNotice.version,
  privacyAcknowledged: true,
  turnstileToken: tokenFromWidget,
};

validateAppraisalSubmission(submission, form);
const receipt = await client.appraisals.submit(dealershipSlug, submission, { idempotencyKey });
// receipt.accepted is true. Retain receipt.reference and any photo instructions separately.
```

`getForm(dealershipSlug, options?)` returns enabled/disabled configuration, dealership/company names,
privacy notice, Turnstile settings, contact/message limits and photo policy. Unknown/archived dealerships
return 404. Privacy fields retain the nullable pinned contract shape. Disabled forms have only enabled.
Photo support can be disabled while text-only submissions remain available.

`submit(dealershipSlug, submission, { idempotencyKey, signal?, timeoutMs? })` validates structure and sends
one request. The UUID key is required and never generated by the SDK. Customer/contact validation is
shared with inquiries: at least one contact, at most one phone and email, local phone country code,
a usable preferred channel and explicit acknowledgment. The server owns contact validity and normalization.

Vehicle descriptions, model year, city and condition are required. VIN and plate are optional/nullable.
Known odometer values require both value and `km`/`mi` unit; unknown values can be omitted/null. Expected
price is a positive decimal USD string representing the seller's asking price, never a calculated value.
Private workflow fields are rejected. Entered data is not normalized by the SDK.

`validateAppraisalSubmission(submission, form)` additionally checks current notice version, admission,
name/message/contact limits and photo availability, count, MIME types and size limits. It is pure and
explicit; submit neither fetches nor caches a form. The server rechecks all admission rules.

## Optional photos

Select files before submission and include metadata in the original submission:

```ts
const declared = {
  filename: file.name,
  contentType: "image/jpeg" as const, // Must match the actual File MIME type and form policy.
  byteSize: file.size,
  altText: "Front view",
};
const withPhoto = { ...submission, photos: [declared] };
validateAppraisalSubmission(withPhoto, form);
const receipt = await client.appraisals.submit(dealershipSlug, withPhoto, { idempotencyKey });
const photo = receipt.photos[0];

if (photo?.state === "upload_available") {
  await client.appraisals.uploadPhoto(photo, file, declared);
  await client.appraisals.completePhoto(dealershipSlug, receipt.reference, photo);
}
```

This is an alternative to the text-only submit example, not an additional submission under that same
key. Keep each selected file paired with its declared metadata and corresponding receipt photo.

The receipt states are `upload_available`, `temporarily_unavailable`, `upload_closed` and
`completion_accepted`. Only upload_available contains upload instructions. No public operation can add
new photo slots after submission. Replaying the original submission can recover instructions within
the original window, but never renews that window.

`uploadPhoto(photo, file, declared, options?)` sends a raw File/Blob via PUT to the signed HTTPS URL.
It verifies the available state, expiry, method, MIME type and declared size. The caller must supply the
original metadata; the server's signature ultimately enforces the original reservation. Signed headers
are preserved, with Content-Length left to the browser. Do not use FormData. Credential headers are
rejected; SDK requests omit cookies, disallow redirects and do not send the completion token to storage.
The configured fetch adapter handles both API and storage requests and must forward RequestInit.

`completePhoto(dealershipSlug, reference, photo, options?)` posts the token in Authorization only to the
exact organization/dealership/reference/photo completion path. It checks expiry and refuses mismatched
paths. It returns `{ accepted: true }`, acknowledging queueing, not successful image processing.
Completion is separate and idempotent. No helper automatically retries, uploads other files, or completes
an upload. Each request supports the shared cancellation and deadline options.

An accepted submission stays accepted if a later photo upload fails. Show these outcomes separately.
Keep receipts and tokens in application memory; do not log or persist signed URLs or tokens by default.
There is no public polling API for processing results. Staff arrange further photos after upload closure.

## Recovery and deployment

For an uncertain submission outcome, retain the key and business payload. A fresh Turnstile token may
accompany an explicit retry. Changed input under the same key returns 409. Review changed privacy notices
before a new submission. Do not resubmit with a new key merely because photo upload or completion failed.

Storage writes are write-once. If a PUT response is lost, a repeated PUT may return 412 because the first
write succeeded. For the same photo/file, completion can be attempted explicitly within its window;
server checks and processing remain authoritative. An uncertain completion can be retried with the same
receipt/token before expiry. Never treat completion acknowledgment as proof of final image processing.

Errors use OrimetricsError. API errors retain safe status/code/request ID/Retry-After diagnostics.
Storage failures expose status only, without parsing response bodies that may contain signed URL data.
Local invalid/expired upload instructions throw TypeError. Cancellation after dispatch and timeout do
not establish that a submission or upload failed. The SDK uses the local clock for expiry checks.

API CORS must allow the website origin, Content-Type, Idempotency-Key and the completion Authorization
header. Storage CORS must allow PUT, Content-Type and If-None-Match from the website. Storage, image
processing and Turnstile must be configured in the deployment. Unit/package tests mock these services;
real CORS, signed uploads and image processing require deployment verification.
